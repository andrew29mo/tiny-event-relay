# Reviewed native macOS validation

Direct native macOS ARM64 run; no Linux, container or VM measurements are mixed in. This is the reviewed implementation and schema 2 report identified by `validation.json`.

- 43 formal tests: 23 launch production relay/receiver processes, three exercise the actual production Store, 13 check report/sampling behavior, and four exercise validator failure/timeout/orphan/interruption cleanup. No skips, errors or missing successes.
- Five isolated behavior mutations detected by assertion failures, not setup failures or timeout.
- 18 fresh-database trials: three scenarios × two blob sizes × three repetitions, 60 events/trial at planned 15/s. All 1,080 accepted IDs/hashes match exactly one committed effect. No trial from the run is omitted.
- Post-COMMIT completion observations use the host-wide monotonic clock, immediately after transaction commit returns. The business ledger/receipts persist; timing observations are in-memory telemetry. Wall timestamps are diagnostic only. JSON retains both scheduled and actual-invocation p95s.
- Expected payload bytes are generated by an independent standard JSON reference. The live contents oracle reads and decodes the real receiver database; a payload-loss mutant must fail.
- Actual normalized relay CLI args are retained. Timing overrides are 0.3 s timeout, 0.05 s base and 0.2 s retry cap; queue/receipt quotas remain at defaults. The receiver uses 3 ms response delay, including on recovery. Drain includes receiver startup.
- Nominal 10 ms samples cover the full declared experiment with a maximum allowed 100 ms gap. Both relay lifetimes must have positive RSS samples with matching PID/creation time. Exceptions or missing coverage fail validation. Initial startup precedes measurement; restart startup is inside its window. Short peaks may still be missed.
- Disk counts apparent DB/WAL/SHM lengths, not filesystem blocks, device writes or endurance. After-drain file sizes are also retained. RSS excludes receiver/client/kernel/filesystem cache; it is not total deployment memory.
